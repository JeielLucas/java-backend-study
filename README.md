# Java & Backend Study

> Trilhas, exercícios e pequenos projetos de estudo em Java, Spring Boot e desenvolvimento backend/full-stack.

Este repositório registra minha retomada e evolução prática em programação. Aqui ficam exercícios, pequenos experimentos, casos de teste e anotações.

## Objetivo

Consolidar fundamentos de Java e backend para me preparar para oportunidades de estágio avançado ou desenvolvedor júnior, construindo evidências práticas que eu consiga explicar em entrevistas.

## Trilhas

- [ ] 01 — Fundamentos de lógica e Java: tipos, operadores, condicionais, laços, métodos, arrays e strings.

- [ ] 02 — Java Core: orientação a objetos, coleções, exceções e organização de código.

- [ ] 03 — SQL e modelagem: consultas, relacionamentos, restrições e PostgreSQL.

- [ ] 04 — Spring Boot e APIs REST: endpoints, validação, tratamento de erros e autorização.

- [ ] 05 — Testes: casos positivos, limites, erros e testes automatizados.

- [ ] 06 — Git, Linux, Docker e CI/CD: fluxo de trabalho, contêineres e automação de build/testes.

- [ ] 07 — Frontend integrado: HTML, CSS, JavaScript, TypeScript e React.

- [ ] 08 — Webhooks e integrações: HTTP, eventos, assinatura, idempotência, tentativas e falhas.

- [ ] 09 — Próximos passos: AWS/cloud, redes, arquitetura, padrões, NoSQL e IA aplicada.

## Semana de retomada

- [ ] Lógica, variáveis, tipos, entrada/saída e operadores.

- [ ] Condicionais e lógica booleana.

- [ ] Laços de repetição.

- [ ] Métodos e decomposição.

- [ ] Arrays e strings.

- [ ] Coleções e orientação a objetos.

- [ ] Miniaplicação de tarefas no terminal e revisão.

Os enunciados ficam nas pastas das trilhas. Para cada exercício, registro exemplos de entrada e saída, casos testados e dúvidas, sem misturar todas as soluções no README principal.

## Como estudar neste repositório

1. Resolver primeiro o enunciado sem procurar uma solução pronta.

1. Registrar exemplos de entrada/saída e testar valores de limite e entradas inválidas quando fizer sentido.

1. Anotar dúvidas e decisões que eu consiga explicar com minhas próprias palavras.

1. Fazer commits pequenos, com mensagens que descrevam a mudança, por exemplo: `feat: add leap-year exercise` ou `docs: record boundary cases`.
